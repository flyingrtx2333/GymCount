# 连续训练与晚间提醒

2026-10-27。本轮为本地功能改动，尚未提交或发布；已发布的 TestFlight 仍为 1.1.5 (49)。

## 行为

- 手机记录页在记录数量旁显示连续训练天数；手表首页收进原有标题区，不增加卡片或挤占三个动作入口。沿用白金配色，支持中英文及系统字体缩放。
- 已保存且实际次数大于零的记录才算训练。按设备本地自然日去重，不区分动作；同日多组不重复加天。未来记录和零次记录不算打卡。
- 今天尚未训练时保留截至昨天的连续天数；直到今天结束仍没训练，次日归零。补记、修正、删除、恢复及同步后按当前有效记录重新计算。趋势页的连续值复用相同计算，仍遵从该页当前筛选。
- 手机默认启用 20:00 未训练提醒，首次使用请求系统通知权限；设置中可关闭。权限拒绝和保存失败显示简短操作入口，不显示假成功。
- 当天已有训练，移除当天待发提醒；尚有连续训练时使用“已连续训练 N 天，今天动一动，延续连动。”，没有连动则使用普通训练提醒。不猜测未来连续天数。
- Watch 原有独立提醒改为相同的条件提醒；新默认时间为 20:00，未明确开启时关闭，保留用户明确保存过的开关与时间。手机通知按系统规则呈现在配对手表上，不默认双端各发一条。

## 接入与持久化

`TrainingActivity.swift` 共用于手机与手表。手机训练存储在原子持久化成功后才发出日期变化回调，后台同步接收也使用同一入口。保存失败不取消提醒。当天已训练的取消动作先执行，再异步续排；提醒队列串行替换并丢弃过期请求，避免旧任务补回已取消的提醒。Watch 记录持久化后的历史更新、应用激活、跨日及时区改变也刷新计划。前台通知再次检查当天是否已有训练。

使用系统本地通知，预排未来 60 个自然日的单次请求，并为其他通知保留额度；不使用无法单独跳过今天的每天重复通知。每次记录变化、后台接收及打开 App 续排。长期完全不运行、也没有后台同步超过该窗口后，需要再次打开应用续排；不承诺无限期离线提醒。系统通知权限、专注模式及通知摘要仍由系统控制。

没有更改训练快照版本、备份格式、Watch 通信协议或计数算法。训练尚未保存或尚未传到手机时，手机不能将其视为已有训练。本轮没有新建模拟器、覆盖用户真机安装或上传训练资料。
