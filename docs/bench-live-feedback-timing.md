# 卧推实时完成反馈与标注时间核对（2026-10-21）

## 行为

- 整组及结束计数继续使用原 V8，迟到的确认、补算与人工修改不触发自动次数震动。
- 普通训练和数据采集共用独立的因果反馈器 `bench-live-top-return-20261021-v1`。只读取当前及过去的融合采样；先确认下降、推起，再回到顶部参考姿态并保持约 0.25 秒，最多触发一次。
- 新反馈不等待两次成组确认。准备时的开始/结束点击反馈已从卧推入口移除。手动按钮、错误及上传状态的独立反馈保留。
- 采样缺口或投递延迟超过 0.25 秒重置反馈状态；主线程再次检查会话代号、运行状态和时间新鲜度。结束重算没有反馈入口。
- 顶部参考自动从稳定姿态取得。当前保守的表面方向门限只在现有佩戴记录上回放验证；不能据此宣称所有手腕姿态、负重或动作幅度均已验证。

## 时间数据

新卧推采集增加可选 `feedback_events` 和 `feedback_algorithm_version`。时间在调用 WatchKit 震动时记录，使用相对于原始采样起点的系统 uptime；它是震动请求时间，不是硬件物理起振时间。与 V8 事后估计的 `detected_events` 分开保存。

旧文件和已有训练记录不改写；没有反馈时间的旧记录显示“未记录”，不能用估计完成点伪造历史震动。

后台先部署兼容新可选字段的 schema，再发布新 App，否则现有严格 schema 会拒绝新增字段。
