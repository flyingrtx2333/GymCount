# 采集授权反馈修复

## 已确认的问题

原“重试授权”始终重复调用 HealthKit 授权接口，并固定显示“请确认系统弹出的授权窗口”。Apple 文档明确：所有请求类型均已作出允许或拒绝选择时，接口返回但不再弹窗。因此旧界面会把没有系统弹窗误表现为等待用户确认。

原授权通过的提前返回不清理旧失败提示，且页面只在出现、切回前台时刷新权限；手机设置变更时，手表留在前台可能保持旧界面。准备指令还可能返回不属于授权流程的旧 message。

采集 ScrollView 忽略顶部安全区域，滚动按钮会进入系统时钟区域。

## 修复

- 授权请求由可见且在前台的采集页面发起，通信回复仍立即返回，不等待用户操作。
- 查询系统是否需要弹窗；已决定的权限只检查实际写入状态。接口成功完成不视作权限已授予。
- 合并冗余授权按钮与提示，只保留开始采集及同步入口。未授权、检查错误使用一次明确弹窗；错误代码写入安全日志，不记录健康数据。
- 授权反馈单独管理，权限变化清理授权提示，不覆盖上传结果。前台每两秒刷新状态，不重复发起系统授权请求。
- 固定采集标题，滚动区域位于标题下方，保留紧凑顶部布局。

## 验证与限制

`build/AuthorizationFixWatch-verified.xcresult`：9 项测试通过，包含首次授权、拒绝后系统不再弹窗、请求成功但权限拒绝、权限改变后清理旧提示且保留上传反馈、错误反馈、准备指令及上传保留。

40mm / 46mm 使用真实 CollectionPanel 的隔离副本验证首屏与底部滚动位置。底部截图通过副本的 defaultScrollAnchor 设置滚动初始位置，未声称验证真实手势。副本未请求健康权限、启动传感器或上传。

设备查询确认当前实体手表安装 `com.flyingrtx.GymCount.watchkitapp`，版本 1.1.3 (20)。未直接读取其 HealthKit 写入状态，手机截图全开与手表拒绝提示之间的实际系统差异仍需真机反馈验证。模拟器不替代真机授权验证。

依据：[Apple HealthKit 授权接口文档](https://developer.apple.com/documentation/healthkit/hkhealthstore/requestauthorization(toshare:read:completion:))。
