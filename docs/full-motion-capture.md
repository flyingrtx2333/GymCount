# 完整运动数据采集（协议 v2）

目标：Watch 只负责可靠采集和人工标注；算法先在云端开发、离线回放与验证，再部署到 Watch 验证。现有识别次数只是对照，不是采集成功条件。

## 采集内容

- `samples`：原始加速度 XYZ，单位 g，包括重力。
- `gyroscope_samples`：原始陀螺仪 XYZ，单位 rad/s。
- `motion_samples`：Core Motion 融合输出，包括重力、去重力加速度（g）、旋转速度（rad/s）、roll/pitch/yaw（rad）、四元数 XYZW、磁场（μT）及其校准状态、heading（度；-1 表示不可用）。
- `magnetometer_samples`：硬件支持时的原始磁场 XYZ，单位 μT。
- 每路单独记录 `t`（传感器时间）与 `received_t`（回调接收时间）。共同时间原点为首个加速度样本，其他流早于原点的数据不写入。不得按数组索引对齐不同信号。
- 姿态参考系固定为 `xArbitraryZVertical`。Yaw 是相对姿态，不是绝对地理方向。
- 记录硬件可用性、佩戴手腕、表冠方向、设备/系统/App/算法版本、随机采集者标识、动作速度和人工备注。

请求每路 40 Hz；实际采样率以服务器统计为准。不支持的传感器对应空数组和 `sensor_availability=false`，禁止补零冒充真实采样。支持但没有足够数据、出现传感器错误或缓冲溢出时，页面报告采集不完整。

## 采集步骤

1. 专用采集包 → 设置 → 采集测试。
2. 选择深蹲、卧推、硬拉、弯举，或者静止、走动、其他非训练样本。
3. 选择正常、慢速、快速或混合速度；备注可填写握持方式、负重等。
4. 保持采集页在前台，每组前后留少量静止片段。单组最多 3 分钟，到时自动进入确认页。
5. 训练样本人工确认真实次数；非训练样本固定为 0。
6. 确认并上传。先原子写入本地文件，上传成功才删除本地待传文件；失败可以重试。

旧算法的触发点最多保留 500 个，超出时记录 `reference_events_truncated=true`，不因此丢弃原始采样。采集版本 v2 不上传 HealthKit 或心率数据。视频需要另行拍摄；当前没有视频上传或逐次动作时间标注入口。

## 云端接收与检查

`POST https://api.flyingrtx.com/api/v1/gymcount/sessions`，JSON 上限 16 MiB。接口保留 v1 接收能力，v2 不需要数据库结构迁移，原始记录仍以 gzip 保存。已有 v1 记录的 canonical SHA-256 保持不变，旧待传文件可继续重试。

后台 `/admin/gymcount` 可切换信号查看波形、查看每路的点数、实际 Hz、最大采样间隔、最大投递延迟与起止时间，并导出完整 JSON。姿态图的 XYZ 对应 roll/pitch/yaw。磁场校准状态、heading、接收时间保留在原始导出中。

先检查数据缺口与投递延迟，再检查标注；不要把算法识别为 0 当成采集无效。开发集与验证集应按采集者或完整采集批次划分，避免同一组数据被拆入两边。

## 发布顺序与回退

先发布支持 v1/v2 的服务端，再发布前端，最后分发采集包（本次构建号 6）。否则新包会被旧服务端拒绝为 422；待传文件保留，服务端升级后可重试。

需要回退 Watch 时可以使用旧版采集包；新版服务端继续接收 v1。云端已有 v2 记录不能在回退时删除。服务端不能回退到只接受 v1 的版本，除非已经停止新客户端的上传。
