# iOS 记录与趋势性能修复 · 2026-11-13

已随 iPhone／Watch 1.1.8 (62) 发布至 TestFlight，包含接收队列与图表高度修复。源码提交 `f2b2ca4f482fc5dbbe3f9bf2ef1bf295e6f71708` 已推送；用户设备安装及训练数据未覆盖。[发布凭证](testflight-1.1.8-62.md)。

## 原因与修改

- 每次后台收件都发布 `storageBusy`、相同记录快照和空错误状态。使用真实 127 条记录重复收件 100 次，修改前产生 400 次存储模型通知并重写快照；即使历史未变，记录页与趋势页仍被唤醒。现在内部事务门不再广播，快照与错误仅变化时发布；重复来源仍验证，磁盘快照存在且内容无需更新时跳过写盘。文件缺失或变为目录时仍尝试原子保存，失败不确认接收。
- 记录页原先在视图计算中多次过滤、分组全部历史。现在按历史版本、筛选、前台恢复、日期／时区变化刷新缓存；筛选直接定位结果，不为整份列表执行重排动画。
- 趋势的选点、滚动位置与主页面共用状态，使连续交互重算整页。提取 `RecordTrendChartSection`，交互状态由图表区域持有；统计仍仅在记录／筛选变化时更新。原有菜单、选点跳转、空值、可访问性和固定高度保留。
- 热图绘制每个单元格时反复求当天、范围与周起点。现在在绘制前确定边界、间距与颜色，只绘制当前视口的单元格；月份标签、日期定位和无障碍操作保留。

## 同数据对照

大屏复用模拟器 `CD183797-B641-447D-A898-1CB5DEDD99DA`，iOS 26.5，Release，独立应用与存储，127 条真实记录。滚动／横向滑动各重复 3 次；CPU 为 `XCTCPUMetric` 的进程累计 CPU 时间，不是帧率或单帧耗时。

| 同一操作 | 修改前 | 修改后 | 本轮均值变化 |
| --- | ---: | ---: | ---: |
| 记录页滚动 CPU | 3.237 s | 2.927 s | -9.6% |
| 趋势页滚动 CPU | 2.058 s | 1.957 s | -4.9% |
| 图表横向滑动 CPU | 3.717 s | 2.315 s | -37.7% |
| 100 次重复收件的模型通知 | 400 | 0 | 消除无效通知 |
| 同一重复收件回放（本机） | 1.108 s | 0.024 s | -97.9% |

趋势页滚动的均值差异较小，接近基线波动，不扩展为真机帧率结论。图表对照只切回原有图表／日历源码，数据、手势脚本及其他页面保持同一版本。模拟器未返回可用的 `XCTHitchMetric` 数值，不宣称已测得真机掉帧率。
