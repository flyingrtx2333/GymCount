# 卧推实时次数与完成反馈同步

2026-10-31，代码与验证完成，未发布。此修复不在此前上传的 1.1.7 (53) 中。

## 原因与改动

原来屏幕次数来自 V8 前缀分析，完成反馈来自另一条因果顶部检测：前缀分析会在动作结束数秒后一次确认两次，而振动早已单独触发或被新鲜度保护丢弃。因此数字增加不代表有一次同时发生的完成反馈。

- 普通训练、整场训练和采集共用同一个新鲜顶部完成事件：增加实时次数，同时请求系统 `directionUp` 触觉反馈；保留其系统音效行为，遵循手表静音设置，不增加语音报数。
- 实时完成事件带上真实周期的起点、转折与完成时间，供时长、分组和结束核准匹配；普通训练先更新内存次数并请求反馈，再写草稿，避免文件写入把反馈拖到下一次下放。
- V8 前缀结果继续用于诊断，不再静默改变实时次数。结束、暂停或切换动作时仍用原 V8 核准，核准没有动作完成反馈入口。
- V8 尚无法确认的一次动作不当作 0 次，保留已收到的实时完成记录；手动加减和每次的重量继续沿用既有匹配规则。
- 采样迟到、停止中、旧会话及暂停保护保留；准备动作不因数字变化而补振动。顶部判定门限和 V8 算法均未调整。
